# P6.4 Controlled Adoption Pilot

**Status:** PASS — published-RC4 adoption, external-Agent qualification, and
hosted Windows/Ubuntu portability gates pass
**Date:** 2026-07-27
**Decision:** AOS is usable through the released distribution on representative
empty, generic, and Rust repositories. A real provider-neutral Agent workflow
also succeeds, but the measured Agent token footprint remains an optimization
target. Production-like and production readiness remain unclaimed.

## Objective

P6.4 tests adoption rather than adding another Core capability:

```text
published RC4
→ one-command install and setup
→ governed Knowledge and Work
→ deterministic context and reference extensions
→ provider-neutral Agent brief
→ real Agent task and independent verification
→ owned uninstall with downstream .aos retained
```

The pilot must not change AOS contracts, grant authority to an Agent, mutate
source during setup or extension execution, or synthesize P6.2 elapsed time.

## Boundaries and remaining work

- P6.4 adds harnesses and evidence only; no new Core execution or authority
  path is introduced.
- P6.2 remains active on its pinned, real-duration lane. P6.4 samples do not
  count toward its seven elapsed days.
- P7 remains planned. No distributed-runtime bottleneck has been proven.
- Hosted CI run
  [`30277600563`](https://github.com/nguyentan510/aos/actions/runs/30277600563)
  passed the structural adoption harness on fresh Windows and Ubuntu runners
  for implementation commit `bee4e369c20d0ada2fb9415e2a7573ce1825e77a`.
- The external Agent gate is intentionally not run in ordinary CI because it
  depends on provider authentication and quota. Its immutable run artifact is
  stored outside the source repository.
