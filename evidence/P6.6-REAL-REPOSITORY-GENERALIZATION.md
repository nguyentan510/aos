# P6.6 Real Repository Generalization

**Status:** `COMPLETE`
**Opened:** 2026-07-27
**Closed:** 2026-07-28
**Core semantics changed:** No
**Production-ready claim:** Not made

## Purpose

P6.6 tests whether the bounded P6.5 consumer capsule generalizes beyond its
three original AOS tasks. The qualification matrix binds 15 patch-and-test
tasks to three immutable repository snapshots:

| Repository | Fixed commit | Tasks |
| --- | --- | ---: |
| AOS | `f7de2d56cf1b400b47cb316f429e8bc38b0b5c8c` | 5 |
| `trenux_rust` | `3297389bd35ff3e8eb129dc74308ec3c8d165bf2` | 5 |
| TRENUX | `020b1ca41824bd0e13d7552136ec6fd1b8ba5f20` | 5 |

Each repository has onboarding, architecture-owner, bugfix, feature, and
documentation-consistency tasks. Every task declares its expected mutation
scope and an independent verification command. Baseline and AOS modes run
twice, producing 60 consumer executions when the gate is complete.

The TRENUX source worktree contained user changes when P6.6 opened. P6.6 never
uses or modifies that worktree. It clones the fixed Git commit into an isolated
snapshot without local hardlinks.

## Implemented qualification controls

- [`benchmarks/p6-6/scenarios.json`](../benchmarks/p6-6/scenarios.json) binds
  all tasks, commits, source boundaries, context records, and verification.
- [`run_p4_ai_facing_benchmark.ps1`](../scripts/run_p4_ai_facing_benchmark.ps1)
  supports multiple scenario IDs, dynamic repository environments, immutable
  clean snapshots, the P6.5 bounded capsule, command/MCP metrics, exact patch
  scope, and consumer-quota fail-fast behavior.
- [`evaluate_p6_6_real_repository_generalization.ps1`](../scripts/evaluate_p6_6_real_repository_generalization.ps1)
  requires three repositories, 15 scenarios, 60 executions, two repeats,
  complete verification, scope isolation, repeat stability, and aggregate
  token/time/command thresholds.
- [`run_p6_6_evaluator_smoke.ps1`](../scripts/run_p6_6_evaluator_smoke.ps1)
  exercises the evaluator deterministically in hosted CI without calling an
  external consumer.

The final thresholds are:

```text
Total input-token reduction >= 25%
Elapsed-time reduction >= 20%
Command reduction >= 20%
Task-success regression <= 5%
All AOS-mode tasks and independent verification pass
All AOS-mode source scope checks pass
Zero AOS-mode MCP calls
Identical prompt SHA-256 across repeats
Aggregate AOS workload input-token drift <= 10%
Maximum per-scenario drift reported as a diagnostic
```

### P6.6.1 resumable runner

The onboarding and architecture-owner executions are now imported into a
fail-closed resume checkpoint:

```text
Eligible complete scenarios: 2
Preserved executions:         60/60
Remaining v1 executions:      0
Verification replay:          PASS
Prompt/event/patch digests:    PASS
```

The checkpoint keys every execution by scenario, mode, and repeat. Reuse
requires the same model/provider package, Agent policy, repeat count, scenario
digest, repository commit, exact changed-file scope, and SHA-256 digests for
the prompt, event JSONL, and patch. Only successful independently verified
executions are stored. Quota errors and failed/partial executions are never
checkpointed.

The resume smoke proves valid reuse, fail-closed artifact tamper denial, and
conflicting-duplicate denial:

```text
AOS_P6_6_RESUMABLE_RUNNER_OK
```

Runner proof `p4-ai-20260728T041649Z` loaded all 8 preserved executions without
calling the consumer again and emitted only the batch marker
`AOS_P6_6_CONSUMER_BATCH_OK`. This proves recovery behavior, not the final P6.6
generalization gate.

P6.6.1 implementation commit
`ff25870e0302108d45fe795fc7156583209c198f` passes GitHub Actions run

## Resume command

Set the three repository locations, then run repository-sized batches after
consumer quota is available:

```powershell
$env:AOS_REPO = 'D:\AOS'
$env:TRENUX_RUST_REPO = 'D:\trenux_rust'
$env:TRENUX_REPO = 'D:\Project\TRENUX'

.\scripts\run_p4_ai_facing_benchmark.ps1 `
  -ManifestPath .\benchmarks\p6-6\scenarios.json `
  -OutputDir D:\AOS-PILOT-EVIDENCE\p6-6-real-repositories\resume `
  -AosBinary .\target\debug\aos.exe `
  -ScenarioId '<comma-separated repository task IDs>' `
  -Repeats 2 `
  -AgentPolicy p6.5 `
  -CheckpointPath D:\AOS-PILOT-EVIDENCE\p6-6-real-repositories\resume\p6-6-checkpoint.json `
  -Resume
```

After all 15 scenarios have valid results:

```powershell
.\scripts\evaluate_p6_6_real_repository_generalization.ps1 `
  -ResultPath <AOS.json>,<TRENUX_RUST.json>,<TRENUX.json>
```
