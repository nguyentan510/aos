## Objective

P6.2 qualifies the completed declarative-local extension slice under bounded
operational conditions:

- interrupted writes must fail closed without losing the recovery path;
- recovery must retain manifest, authority, Work, Run, and Audit provenance;
- a reconciled extension Work must be safely replayable with a new immutable
  Run and Extension Result revision;
- repeated fixed-snapshot pilots must expose latency and control-data growth;
  and
- the duration gate must accumulate real elapsed time instead of being
  satisfied by a same-day smoke.

This scope remains local-only. It does not add network access, arbitrary
commands, provider mutation, distributed execution, or production authority.

## Recovery hardening

An idempotent extension enable now requires all four persisted facts:

```text
enabled lifecycle
+ matching immutable manifest digest
+ matching Governance enable decision
+ matching Audit enable event
```

If lifecycle reached `enabled` but Governance or Audit was interrupted, the
next governed enable revalidates the manifest, appends recovery lifecycle
revisions, and records digest-bound Governance and Audit evidence. It emits:

```text
extension:incomplete-trace-recovered
```

Reconciliation decisions for extension Work now retain the immutable extension
reference, manifest digest, capability, resource scope, and previous authority
basis. Run revision discovery uses the persisted Run identity, so a resolved
Work writes a new Run and Extension Result revision instead of colliding with
the interrupted attempt.

## Filesystem fault-injection gate

The process tests inject an ordinary file where AOS expects each tested
directory:

| Boundary | Expected behavior | Local result |
| --- | --- | --- |
| Manifest snapshot | Exit 8, no unsafe continuation, retry succeeds | PASS |
| Lifecycle revision | Exit 8, retained manifest is reusable | PASS |
| Governance trace | Partial enable is detected and repaired | PASS |
| Audit trace | Partial enable is detected and repaired | PASS |
| Extension Result | Work becomes blocked with reconciliation required | PASS |

After restoring the Result boundary, an attributable reconciliation returns the
Work to `authorized`; replay completes and persists result revision `r2`.

Canonical command:

```powershell
.\scripts\run_p6_2_fault_injection_gate.ps1
```

Markers:

```text
AOS_P6_2_FILESYSTEM_FAULT_INJECTION_OK
AOS_P6_2_RECONCILIATION_OK
```

This is deterministic filesystem boundary injection. Forced process
termination at every instruction boundary and real disk-full hardware
qualification remain outside the current proof.

## Qualification rule

The default installed pilot can move from `ACTIVE` to `QUALIFIED` only when:

```text
elapsed wall-clock duration >= 7 days
passed samples >= 7
failed samples = 0
sample result integrity failures = 0
every nested P6.1 pilot reports deterministic replay
every nested P6.1 pilot reports zero source mutation
```

Only then may the harness emit:

```text
AOS_P6_2_DURATION_GATE_OK
```
